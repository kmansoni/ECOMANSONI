# Политика конфиденциальности платформы Mansoni

Версия: 1.0  
Дата вступления в силу: 01 июня 2026  
Оператор: ООО "Mansoni" (ОГРН [TBD], ИНН [TBD], 127051, РФ, Москва, ул. Петровка, д. 24)

## 1. Общие положения

Настоящая Политика конфиденциальности ("Политика") определяет порядок обработки персональных данных и защиты конфиденциальной информации Пользователей платформы Mansoni (далее "Платформа") в соответствии с ФЗ № 152 от 27.07.2006 "О персональных данных", ФЗ № 149 от 27.07.2006 "Об информации, информационных технологиях и защите информации", ФЗ № 115 от 07.08.2001 "О противодействии легализации доходов, полученных преступным путем", а также иными применимыми нормативными правовыми актами РФ.

Платформа включает модули: мессенджер (с End-to-End шифрованием), социальную сеть (Reels, ленту), знакомства, такси, маркетплейс, CRM, страхование, стриминг видео, недвижимость, а также AI-ассистента.

## 2. Категории обрабатываемых персональных данных

### 2.1 Обязательные данные (для функционирования Платформы)

- **Регистрационные данные**: номер телефона, адрес электронной почты, имя Пользователя, аватар, статус профиля.
- **Данные аутентификации**: хеши паролей, OTP-токены, сессионные токены, биометрические данные (при согласии Пользователя и на мобильной платформе).
- **Профильные данные**: место жительства, пол, возраст (год рождения), статус "онлайн", последнее время активности, язык интерфейса.
- **Технические данные**: Device ID, IP-адрес, тип операционной системы, версия приложения, User-Agent, логи ошибок, метрики производительности.
- **Данные о платежах**: история платежей, сумма, дата, идентификатор транзакции, способ оплаты (токены кредитных карт хранятся у платежного провайдера, Оператор не имеет доступа к полным реквизитам).

### 2.2 Контент и коммуникации (End-to-End Encrypted)

- **Сообщения**: текст, эмодзи, упоминания (@), цитирования. Сообщения шифруются end-to-end с использованием Web Crypto API и приватных ключей, хранимых локально на устройстве Пользователя. **Сервер Оператора не имеет доступа к открытому тексту сообщений.**
- **Медиа**: фотографии, видео, аудиозаписи, документы, отправляемые в мессенджере или публикуемые в ленте. Медиа загружаются на Supabase Storage с RLS-защитой (см. раздел 8).
- **Метаданные коммуникаций**: временные метки отправки/доставки/прочтения, статус "печатает", информация о реакциях (лайки, эмодзи) — эти данные хранятся в зашифрованном виде и не могут быть просмотрены Оператором.

### 2.3 Данные о поведении и предпочтениях

- **История запросов**: маршруты поиска, избранные места, история покупок в маркетплейсе, история заказов такси.
- **Параметры использования**: какие модули используются, время использования, язык, тема оформления (светлая/тёмная), количество контактов.
- **Данные о предпочтениях**: выбранные категории товаров, фильтры маршрутов, предпочитаемые способы оплаты.

### 2.4 Данные безопасности и мониторинга

- **События входа**: дата, время, IP-адрес, географическое местоположение (приблизительное, по IP).
- **Попытки несанкционированного доступа**: неудачные попытки входа, попытки обхода ограничений.
- **Антифрод-данные**: сигналы подозрительной активности, отклоненные платежи, флаги мошенничества.
- **Журнал действий модерации**: жалобы на контент, блокировки, предупреждения, события удаления контента.

### 2.5 Данные о местоположении (только при согласии)

- **GPS координаты**: при использовании функций "Люди рядом" (знакомства), заказа такси, навигации.
- **Данные хранятся временно** (обновляются в реальном времени) и удаляются после завершения сеанса, если Пользователь не выбрал сохранение истории.

### 2.6 Данные третьих лиц

- **Контакты**: если Пользователь синхронизирует контакты с устройства, Оператор получает номера телефонов и имена контактов для функции "друзья из контактов".
- **Данные при приглашении**: если Пользователь пригласит друга, мы обрабатываем номер телефона приглашаемого лица для отправки приглашения.

## 4. Правовые основания обработки

1. **Исполнение договора** (ст. 6(1)(b) GDPR, ст. 7(1)(а) ФЗ-152): Обработка необходима для предоставления услуг, на которые согласился Пользователь.
2. **Согласие Пользователя** (ст. 6(1)(a) GDPR, ст. 9 ФЗ-152): При регистрации, при включении уведомлений, при синхронизации контактов, при использовании GPS.
3. **Законные обязательства** (ст. 6(1)(c) GDPR, ст. 7(1)(в) ФЗ-152): Обработка данных о платежах в соответствии с ФЗ-115, налоговым кодексом РФ.
4. **Законный интерес Оператора** (ст. 6(1)(f) GDPR, ст. 7(1)(е) ФЗ-152): Защита Платформы от мошенничества, улучшение безопасности, исполнение судебных приказов, модерация контента в целях соблюдения закона.

## 6. Шифрование и защита данных

### 6.1 End-to-End Encryption (E2EE)

Сообщения в мессенджере защищены end-to-end шифрованием с использованием стандарта Web Crypto API (AES-256-GCM для симметричного шифрования, ECDH для обмена ключами). Приватные ключи хранятся **локально на устройстве Пользователя** и **никогда не отправляются на сервер**.

- Сервер хранит только зашифрованные сообщения.
- При запросе о раскрытии данных (например, от органов власти) Оператор не может предоставить открытый текст сообщений.
- Экспорт сообщений возможен только Пользователем лично с его устройства.

### 6.2 Row-Level Security (RLS) в Supabase

Все таблицы в базе данных защищены политиками RLS (Row-Level Security), которые гарантируют:

- Каждый Пользователь видит только свои данные и данные, которыми с ним поделились.
- Запросы к БД, инициированные клиентом, автоматически фильтруются по `auth.uid()` (идентификатор Пользователя).
- Edge Functions (серверные функции) выполняют операции от имени сервиса и подчиняются той же RLS-политике.

### 6.3 Передача данных (TLS/HTTPS)

Все коммуникации между клиентом и сервером шифруются с использованием TLS 1.3. API вызовы, загрузка файлов, вход в аккаунт — все происходит по защищённому каналу.

### 6.4 Хранение чувствительных данных

- **Пароли**: хранятся в виде криптографически стойких хешей (bcrypt, минимум 12 раундов).
- **Токены доступа (JWT)**: подписаны и зашифрованы на сервере; обновляются каждые 15 минут.
- **Данные кредитных карт**: не хранятся у Оператора; используется PCI-DSS сертифицированный платежный провайдер.

## 8. Права субъекта персональных данных (Data Subject Rights)

Каждый Пользователь имеет следующие права согласно ФЗ-152 и GDPR:

### 8.1 Право на доступ (Right of Access)

Пользователь может запросить информацию об обработке его персональных данных:
- Какие данные обрабатываются.
- Цели обработки.
- Категории получателей.
- Сроки хранения.
- Право на исправление, удаление, ограничение.

**Порядок реализации**: Пользователь может скачать свои данные непосредственно из приложения (раздел "Экспорт данных" в Настройках) или направить письменный запрос на privacy@mansoni.app.

**Срок ответа**: 30 календарных дней с момента получения запроса (в соответствии с ФЗ-152).

### 8.2 Право на исправление (Right to Rectification)

Пользователь может исправлять неточные данные своего профиля (имя, адрес, номер телефона). Исправления вступают в силу немедленно.

### 8.3 Право на удаление (Right to Erasure, "Right to be Forgotten")

Пользователь может запросить удаление своих данных в следующих случаях:

- Данные больше не необходимы для целей, в которых они собирались.
- Пользователь отзывает своё согласие и отсутствует другое правовое основание для обработки.
- Пользователь возражает против обработки и причины Оператора не перевешивают причины Пользователя.
- Данные обрабатывались незаконно.
- Требуется удаление по закону.

**Процедура**:
1. Пользователь выбирает "Удалить аккаунт" в настройках.
2. Ему предлагается 30-дневный период охлаждения (grace period), в течение которого аккаунт можно восстановить.
3. По истечении 30 дней, все персональные данные удаляются безвозвратно, кроме:
   - Данных, требуемых законом (платежи — 5-7 лет).
   - Данных, необходимых для безопасности и соблюдения закона (логи инцидентов — 1 год).

**Срок ответа**: 30 календарных дней.

### 8.4 Право на ограничение обработки (Right to Restrict Processing)

Пользователь может запросить ограничение обработки данных (т.е. их "заморозку") на время расследования жалобы или спора. При ограничении:

- Данные хранятся, но не обрабатываются.
- Пользователь не получает уведомлений/рекомендаций.
- Аккаунт остаётся неактивным, пока ограничение не будет снято.

### 8.5 Право на портативность данных (Right to Data Portability)

Пользователь может скачать свои данные в структурированном, машиночитаемом формате (JSON, CSV) для передачи другому сервису:

- **Регистрационные данные**: имя, email, номер телефона, дата рождения.
- **Данные профиля**: аватар, описание, статус, настройки.
- **Коммуникации**: список контактов, список чатов (метаданные), история сообщений (только ваши сообщения).
- **Данные о транзакциях**: история заказов такси, покупок в маркетплейсе, платежей.

**Исключение**: Зашифрованные end-to-end сообщения не могут быть портированы в открытом виде (находятся под защитой E2EE).

**Процедура**: Раздел "Экспорт данных" в Настройках → выбрать категории → загрузить архив.

### 8.6 Право возражения (Right to Object)

Пользователь может возражать против обработки данных на основании "законного интереса" Оператора:

- Оператор прекратит обработку, если не докажет наличие более значимых интересов.
- Однако обработка может продолжиться по другим правовым основаниям (исполнение договора, требования закона).

### 8.7 Право отозвать согласие (Right to Withdraw Consent)

Если обработка основана на согласии Пользователя, он может отозвать согласие в любой момент:

- Это не влияет на законность обработки до момента отзыва.
- **Примеры**: отключить push-уведомления, отключить сбор аналитики, отключить доступ к микрофону/камере.

**Процедура**: Каждый тип согласия имеет переключатель в Настройках → Приватность и безопасность.

### 8.8 Право обжаловать решение (Right to Lodge a Complaint)

Если Пользователь считает, что его права нарушены, он вправе:

1. **Направить жалобу Оператору**: privacy@mansoni.app (30 дней на ответ).
2. **Обратиться в уполномоченный орган**:
   - В РФ: Роскомнадзор (https://rsoc.ru) или судом в общем порядке.
   - В ЕС: надзорный орган по защите данных в соответствующей стране.

## 9. Безопасность и защита от утечек

### 9.1 Технические меры

- **Многофакторная аутентификация (MFA)**: OTP по SMS, TOTP, биометрия на мобильных.
- **Мониторинг безопасности**: SIEM система отслеживает подозрительную активность.
- **Регулярные аудиты безопасности**: Пентесты, код-ревью, проверка зависимостей (SBOM).
- **Шифрование в пути (TLS 1.3)** и **в покое (AES-256)**.

### 9.2 Организационные меры

- **Разграничение доступа**: Доступ к данным имеют только сотрудники, имеющие необходимость знания.
- **Соглашения о конфиденциальности**: Все сотрудники и подрядчики подписывают NDAs.
- **Отчетность об инцидентах**: При утечке данных, затрагивающей более 30 субъектов, Оператор уведомляет Роскомнадзор в течение 72 часов.

### 9.3 Процедура реагирования на инциденты

1. **Обнаружение**: Мониторинг 24/7 выявляет подозрительную активность.
2. **Изоляция**: Поддельный аккаунт блокируется, эксплуатируемый сервис отключается.
3. **Анализ**: Команда безопасности определяет масштаб утечки.
4. **Уведомление**: Затронутые пользователи уведомляются о характере утечки и рекомендуемых действиях.
5. **Исправление**: Уязвимость закрывается, данные восстанавливаются из резервной копии при необходимости.
